> 文档定位：本文件是《项目落地方案.md》阶段一的需求细化，聚焦「统一身份认证 + 管理端/用户端双前端 + 权限分配 + 问答反馈闭环」。

> 编写日期：2026-11-12

## 一、阶段目标

一句话概括：

> 让管理员和普通用户使用同一套账号登录。管理员进入功能完整的管理端；普通用户进入纯问答端，可以自选问答策略，但不能选择模型、不能入库；用户在问答过程中遇到的问题可以提交给管理员，管理员在管理端接收、跟踪和处理。

本阶段必须达成以下结果：

1. **一套账号体系**：管理端与用户端共用同一套用户、角色和登录状态，不出现两套账号。
2. **两个前端入口**：管理端展示完整页面与全部功能；用户端只展示问答窗口与反馈入口。
3. **权限真实生效**：不仅前端隐藏菜单，后端接口也必须按角色和资源归属鉴权，直接调用接口不能越权。
4. **用户问答可用**：用户能选择知识库、进行多轮问答、自选问答策略、查看引用来源和历史会话。
5. **用户不能越界**：用户端不出现模型选择、模型配置、知识库管理、文档入库、全局检索策略配置、日志、用户管理、反馈处理等入口；即使伪造请求也会被后端拒绝。
6. **反馈闭环可用**：用户可提交反馈，管理端可查看完整问答上下文、跟踪状态、回复并办结。

## 三、总体形态与双前端定义

### 3.1 双前端定义

本阶段的「双前端」指：

| 前端 | 面向角色 | 定位 | 入口建议 |
| --- | --- | --- | --- |
| 管理端 | admin | 完整管理台与全功能问答 | 独立域名或端口，例如 `/admin/*` |
| 用户端 | user（管理员也可访问） | 纯问答窗口 + 反馈入口 | 独立域名或端口，例如 `/chat`、`/feedback` |

两个前端**共享同一套后端、同一套用户数据、同一套知识库与索引、同一套反馈数据**。不得各自维护一套账号、知识库或反馈表，否则会出现「管理员看不到用户反馈」「管理员维护的知识库用户查不到」等分裂问题。

### 3.2 推荐落地方式

推荐以 `product/` 为主系统：

- 管理端复用 `product/frontend` 现有完整页面。
- 用户端作为独立入口，由 `product/frontend` 裁剪出问答页面，或拆成独立构建产物。
- 两个前端可以共用一个代码仓库，通过构建模式或路由树区分：
  - `VITE_APP_MODE=admin`：仅注册管理端路由，展示完整菜单。
  - `VITE_APP_MODE=user`：仅注册用户端路由，展示问答与反馈入口。
  - 也可以在同一应用内按角色动态挂载路由，但必须保证用户端不加载管理页面代码、不展示管理菜单。
- 后端统一使用 `product/backend`，不新增第二套业务库。

如果希望用户端采用 `agent/` 的问答交互，应将 Agent 能力作为用户端的一种「深度问答」策略接入 `product/backend`，而不是让 `agent/` 单独维护一套知识库、账号和反馈数据。若坚持 `product + agent` 两个独立后端，则统一认证、知识库、反馈必须上移为共享服务，需另行确认，不在本文件默认方案内。

### 3.3 角色访问关系

| 场景 | admin | user |
| --- | --- | --- |
| 登录管理端 | 允许，进入完整管理台 | 拒绝，提示无权限或跳转用户端 |
| 登录用户端 | 允许，可使用问答与反馈 | 允许，进入问答窗口 |
| 访问管理端页面 | 全部允许 | 全部拒绝 |
| 访问用户端页面 | 全部允许 | 仅问答、反馈、个人中心 |
| 调用管理接口 | 允许 | 403 |
| 调用问答接口 | 允许 | 允许，但只能操作自己的会话 |

管理员拥有所有权限，包括访问用户端；普通用户只能访问用户端。管理员登录用户端时，不因页面裁剪而失去管理能力，可通过「返回管理端」入口跳转。

## 四、角色与权限分配

### 4.1 角色定义

本阶段只设两级角色，避免权限模型过度设计：

| 角色 | 标识 | 说明 |
| --- | --- | --- |
| 管理员 | `admin` | 拥有全部权限；可管理用户、知识库、模型、策略、日志与反馈 |
| 普通用户 | `user` | 只能进行问答、策略自选、查看自己的会话与引用、提交和查看自己的反馈 |

数据库中的角色字段应保留扩展空间，后续可增加 `staff`、`dept_admin` 等角色，但本阶段不实现。

### 4.2 权限矩阵

| 功能/资源 | admin | user | 说明 |
| --- | --- | --- | --- |
| 登录、退出、修改自己的密码 | 允许 | 允许 | 共用认证服务 |
| 问答 | 允许 | 允许 | 用户只能使用已发布知识库 |
| 选择知识库 | 全部 | 仅已发布/启用 | 用户不可见未发布知识库 |
| 问答策略自选 | 允许 | 允许 | 用户只能选管理员开放的预设 |
| 深度问答（Agent） | 允许 | 允许（若开放） | 由管理端配置是否对用户开放，最多 3 轮 |
| 选择/切换生成模型 | 允许 | **禁止** | 用户端无入口，后端拒绝 `model` 参数 |
| 模型参数配置、连接测试 | 允许 | **禁止** | 仅管理端 |
| 知识库创建、编辑、删除 | 允许 | **禁止** | 仅管理端 |
| 文档上传、解析、入库、重建、删除 | 允许 | **禁止** | 仅管理端 |
| 全局检索策略配置 | 允许 | **禁止** | 用户只能选预设，不能改参数 |
| 查看检索详情 | 允许 | 仅自己的回答 | 不能查看他人会话 |
| 查看系统/检索日志 | 允许 | **禁止** | 仅管理端 |
| 会话历史 | 自己的会话 | 自己的会话 | 按 `user_id` 隔离 |
| 删除会话 | 自己的会话 | 自己的会话 | 不能删除他人会话 |
| 提交反馈 | 允许 | 允许 | 可关联具体问答，也可做疑难提交 |
| 查看自己的反馈 | 允许 | 允许 | 仅本人 |
| 查看全部反馈、处理反馈 | 允许 | **禁止** | 仅管理端 |
| 用户列表、创建用户、分配角色、禁用、重置密码 | 允许 | **禁止** | 仅管理端 |
| 查看审计日志 | 允许 | **禁止** | 仅管理端 |

### 4.3 权限落地原则

1. **前端三处一致**：导航菜单、路由守卫、页面内按钮必须同时按角色控制，不能只隐藏菜单。
2. **后端为最终裁决**：所有权限判断必须在后端完成；前端隐藏只是体验优化，不能作为安全边界。
3. **默认拒绝**：未明确授权的接口默认拒绝；新增接口必须显式声明所需角色。
4. **资源归属校验**：会话、消息、反馈等资源必须校验 `user_id`；不能只凭 ID 查询。
5. **不信任客户端身份**：用户 ID、角色、部门必须从登录态解析，不能从请求体、查询参数或前端存储中直接采信。
6. **统一错误语义**：未登录返回 401；已登录但无权限返回 403；资源不存在或不属于当前用户返回 404，避免通过错误码探测他人资源。
7. **最小权限**：用户端不加载管理页面代码，不暴露管理接口地址和参数结构。
8. **管理员保护**：不能禁用、删除自己；不能移除最后一个管理员；关键操作需二次确认。

## 五、统一身份认证

### 5.1 账号来源

本阶段支持以下账号来源：

| 来源 | 说明 | 优先级 |
| --- | --- | --- |
| 初始化管理员 | 首次部署通过环境变量或初始化脚本创建 | P0 |
| 管理员创建的用户 | 管理端创建普通用户，设置初始密码 | P0 |
| 批量导入 | 可选，从 CSV 导入用户名、姓名、角色 | P1 |
| 学校统一身份认证 | CAS / 企业微信 / 钉钉 OAuth，通过适配层接入 | 预留，按学校选型 |

要求：

- 不开放用户自助注册。
- 用户名唯一；支持姓名、部门等展示字段。
- 普通用户由管理员创建或从学校身份源同步，不能自行提升角色。
- 初始管理员账号不得使用 `admin/123456` 之类的固定弱口令；初始密码通过环境变量传入，未配置时随机生成并仅在首次启动日志中输出一次，首次登录强制修改。

### 5.2 登录流程

1. 用户访问任意业务页面，未登录时跳转登录页，并记录原始目标地址。
2. 登录页收集用户名、密码，提交到统一登录接口。
3. 后端校验账号状态、密码哈希、失败次数限制。
4. 校验通过后签发会话凭证，返回用户基本信息与角色。
5. 前端按角色跳转：
   - `admin` 登录管理端 → 管理端首页（如 `/admin/chat`）。
   - `admin` 登录用户端 → 用户端问答页，并提供「返回管理端」入口。
   - `user` 登录用户端 → 用户端问答页。
   - `user` 尝试登录管理端 → 拒绝并提示无权限，或直接跳转用户端登录。
6. 已登录用户再次访问登录页，按角色跳转到对应首页。

登录失败提示统一为「用户名或密码错误」，不区分「账号不存在」和「密码错误」，避免账号枚举。

### 5.3 会话与凭证

- 登录成功后签发有时效的会话凭证，建议默认有效期 8 小时，可通过环境变量配置。
- 凭证不得放在 URL 查询参数中；优先使用 `HttpOnly + Secure + SameSite` Cookie；如使用 `Authorization: Bearer`，前端应避免持久化到不安全的存储。
- 退出登录必须使当前凭证失效；服务端应支持撤销，不能只在前端删除本地状态。
- 凭证过期或失效时，业务接口返回 401，前端清理状态并跳转登录页。
- 修改密码后，建议使该用户其他已登录会话失效。
- 账号被禁用后，已签发的凭证应在下一次请求时失效或被拒绝。

### 5.4 密码安全

- 密码必须使用 bcrypt、argon2 等慢哈希算法存储，禁止明文、MD5、SHA1。
- 密码最短 8 位，建议包含字母和数字；管理员重置的初始密码必须要求首次登录修改。
- 登录失败按「用户名 + IP」限流，例如 10 分钟内失败 5 次后锁定 10 分钟；锁定提示不泄露账号是否存在。
- 日志、审计、异常堆栈中不得出现明文密码、完整令牌、Cookie。
- 生产环境必须启用 HTTPS。

### 5.5 接口鉴权

- 除登录接口和健康检查外，所有 `/api/v1/**` 接口默认要求登录。
- 管理接口统一要求 `admin` 角色，建议挂在 `/api/v1/admin/**` 下，便于统一拦截。
- 问答、会话、反馈接口要求登录，并校验资源归属。
- 知识库读取接口需要区分：
  - 用户端：只能列出已发布/启用的知识库。
  - 管理端：可以列出全部知识库。
- 文档上传、解析、入库、删除、重建等接口仅管理员可调用。
- 日志、模型配置、全局检索策略、用户管理、反馈处理接口仅管理员可调用。
- 反馈详情接口：管理员可查看全部；普通用户只能查看自己提交的反馈。
- 建议在开发环境保留 OpenAPI 文档，生产环境关闭或仅管理员可访问。

### 5.6 用户与角色管理

管理端提供最小可用的「用户与权限」页面：

| 功能 | 要求 |
| --- | --- |
| 用户列表 | 分页、按用户名/姓名/角色/状态筛选 |
| 创建用户 | 用户名、姓名、初始密码、角色、可选部门 |
| 分配角色 | 仅允许 admin / user；变更后对该用户下一次请求生效 |
| 启用/禁用 | 禁用后不能登录，已登录会话失效 |
| 重置密码 | 生成临时密码或管理员输入，强制下次登录修改 |
| 删除用户 | 建议不物理删除，改为禁用；如删除，需处理其会话与反馈归属 |
| 自我保护 | 不能禁用/删除自己；不能移除最后一个管理员 |
| 审计 | 创建、改角色、禁用、重置密码均记录操作人、时间、对象 |

如果一期不提供完整用户管理页面，至少必须提供等价的初始化脚本或管理接口，保证「权限分配」可操作、可追溯；不能只靠手工改数据库。

### 5.7 认证源扩展

认证层应抽象为可替换的 `AuthProvider`：

- `local`：账号密码，本阶段默认实现。
- `cas` / `wecom` / `dingtalk`：后续实现，负责跳转、回调、票据校验、用户属性映射。
- 角色映射：学校身份源中的部门/岗位可映射为 `admin` / `user`；必须保留本地管理员兜底账号，避免身份源故障时无法管理。
- 无论使用哪种认证源，业务后端只认统一会话凭证，不直接依赖某个身份源的票据。

## 六、管理端前端需求

### 6.1 页面清单

管理端必须完整展示以下页面，保留现有功能，并新增反馈处理与用户管理：

| 页面 | 路由建议 | 主要功能 | 备注 |
| --- | --- | --- | --- |
| 登录 | `/login` | 用户名密码登录、错误提示、登录后跳转 | 与用户端共用认证 |
| 问答 | `/admin/chat` | 多轮问答、知识库选择、模型选择、策略选择、深度问答、引用查看、检索详情、会话历史 | 现有问答能力不降级 |
| 知识库 | `/admin/knowledge` | 知识库创建/编辑/删除、文档上传、解析、入库、重建、删除、状态查看 | 保留现有能力 |
| 检索策略 | `/admin/strategy` | 全局检索参数配置、策略预设管理、对用户开放开关 | 新增「用户可选预设」概念 |
| 模型设置 | `/admin/model` | 模型来源（云端/本地）、模型名称、参数、连接测试、保存 | 若现有管理端无独立页面，可先做最小版 |
| 日志 | `/admin/logs` | 检索日志、系统日志、筛选、详情 | 保留现有能力 |
| 反馈处理 | `/admin/feedback` | 反馈统计、列表、筛选、详情、受理、回复、解决、驳回 | **本阶段新增页面** |
| 用户与权限 | `/admin/users` | 用户列表、创建、角色分配、启用/禁用、重置密码 | 本阶段新增最小集 |

### 6.2 管理端问答要求

- 管理员可以选择知识库、选择模型、选择问答策略。
- 管理员可以查看检索详情、召回文档、精排结果、耗时等调试信息。
- 管理员可以进入深度问答（Agent）模式，并查看决策轨迹；轮数不超过 3 轮。
- 管理员可以查看自己的会话历史；默认不提供「查看全部用户会话」功能，避免隐私扩散。排障通过检索日志与反馈快照完成。
- 管理端导航必须完整展示所有页面；不能因为用户端裁剪而影响管理端。

### 6.3 管理端交互要求

- 顶部展示当前登录用户、角色、退出入口。
- 管理端与用户端使用一致的视觉语言和主题，但管理端保留完整侧边栏。
- 关键操作（删除知识库、删除文档、禁用用户、重置密码、驳回反馈）需要二次确认。
- 页面加载、空数据、接口错误、无权限要有明确提示，不能白屏。

## 七、用户端前端需求

### 7.1 页面清单

用户端只保留问答与反馈，不出现管理功能：

| 页面 | 路由建议 | 主要功能 | 备注 |
| --- | --- | --- | --- |
| 登录 | `/login` | 用户名密码登录 | 与管理员共用认证；普通用户不能进入管理端 |
| 问答 | `/chat` | 知识库选择、多轮问答、流式回答、引用查看、策略自选、会话历史、反馈入口 | 核心页面 |
| 反馈 | `/feedback` 或问答页内弹窗 | 提交反馈、查看我的反馈 | 形态二选一，见 8.2 |

用户端导航只允许出现：问答、反馈（或「疑难提交」按钮）、个人菜单（修改密码、退出）。不得出现知识库管理、文档入库、检索策略、模型设置、日志、用户管理、反馈处理等入口。

### 7.2 问答功能要求

| 功能 | 要求 |
| --- | --- |
| 知识库选择 | 只能选择管理员已发布/启用的知识库；无可用知识库时给出提示 |
| 多轮问答 | 支持连续对话，保留上下文；支持新建会话、切换会话、删除自己的会话 |
| 流式回答 | 支持逐字/分段展示，支持停止生成 |
| 引用溯源 | 答案必须展示 `[n]` 引用；引用卡片展示文件名、页码/条款、命中片段；点击可查看来源摘要 |
| 检索详情 | 用户可查看自己回答的检索详情（召回、精排、耗时），但不可查看他人 |
| 策略自选 | 用户可在提问前/提问时选择管理员开放的策略预设；回答中标注实际使用的策略 |
| 反馈入口 | 每条回答下方有「反馈」按钮；页面提供「疑难提交」入口 |
| 历史会话 | 只展示当前用户自己的会话；不能看到他人会话 |
| 错误处理 | 401 跳登录；403 提示无权限；网络错误可重试；不得泄露后端堆栈 |

引用点击的权限边界：

- 用户可以看到引用对应的文件名、页码/条款和命中片段。
- 完整原文下载/预览默认仅管理员可用；后续接入文档 ACL 后再按权限开放。
- 不得通过引用接口返回用户无权访问的完整文档内容。

### 7.3 问答策略自选

用户端的「策略自选」不是让用户改检索参数，而是让用户在管理员发布的策略预设中选择：

| 策略预设（示例） | 说明 | 默认对用户开放 |
| --- | --- | --- |
| 快速问答 | 混合检索（向量 + BM25）→ RRF → 精排 → 生成 | 是 |
| 向量优先 | 向量召回 + 精排，适合口语化描述 | 可选 |
| 关键词优先 | BM25 + 精排，适合条款号、文号等精确串 | 可选 |
| 深度问答 | Agent 多轮决策，最多 3 轮，适合多跳/跨文件问题 | 由管理员决定 |

要求：

1. 管理端在「检索策略」页维护策略预设，并设置「对用户开放」开关。
2. 用户端只展示已开放的预设，不展示原始参数（top-k、权重、RRF k、温度等）。
3. 用户选择以 `strategy_id` 形式提交，后端校验该预设存在且已开放；禁止用户提交任意参数覆盖系统配置。
4. 回答返回实际使用的策略名称，前端在答案或检索详情中展示。
5. 默认策略由管理端配置；用户可在本次会话中切换，是否记住用户偏好由实现决定。
6. 深度问答如未接入或未开放，用户端不显示该选项。

### 7.4 用户端明确禁止项

用户端不得出现、不得调用、不得通过参数绕过以下能力：

- 选择或切换生成模型（云端/本地、模型名称、温度、最大 token 等）。
- 创建、编辑、删除知识库。
- 上传、解析、入库、重建、删除文档。
- 修改全局检索策略、RRF 参数、召回数量、精排开关。
- 查看系统日志、检索日志、其他用户会话。
- 查看或处理他人反馈。
- 创建用户、分配角色、禁用账号、重置密码。
- 访问管理端任何页面或 `/api/v1/admin/**` 接口。

后端必须对上述请求返回 403 或 422，不能因为前端隐藏而默认放行。

### 7.5 用户端布局建议

- 顶部：系统名称、知识库选择、策略选择、当前用户菜单。
- 左侧：会话列表（可折叠），新建会话、删除会话。
- 中间：消息流、引用卡片、反馈按钮、输入框。
- 右侧：可选的检索详情面板，默认收起；移动端不要求。
- 整体保持单列问答体验，不出现管理端侧边栏。
- 最低适配 1366×768；本阶段不做移动端 H5。

## 八、反馈功能详细需求

### 8.1 目标与原则

1. **低门槛**：用户发现问题时，最多两次点击即可打开反馈表单。
2. **上下文完整**：自动带入原问题、系统答案、引用、策略、知识库、会话与消息 ID，管理员不用追问「你问的是什么」。
3. **快照可信**：反馈内容由后端按消息 ID 读取并保存快照，不信任客户端提交的答案文本，防止篡改。
4. **闭环可追踪**：每条反馈有工单号、状态、处理人、处理记录；用户可查看自己反馈的进度和管理员回复。
5. **隐私最小化**：用户只能看到自己的反馈；管理员只查看反馈关联的问答快照，不提供全量会话浏览。

### 8.2 用户端反馈入口形态

用户端必须提供反馈提交能力，形态二选一：

| 方案 | 形态 | 优点 | 建议 |
| --- | --- | --- | --- |
| A | 独立页面 `/feedback`，包含提交表单与「我的反馈」列表 | 入口清晰、便于用户回看 | 学校要求独立入口时采用 |
| B | 问答页内「疑难提交」弹窗 + 「我的反馈」抽屉 | 不打断问答、实现成本低 | **本期推荐** |

无论选择哪种形态，表单字段、提交逻辑、状态查询与权限要求一致。管理端必须使用独立页面，不接受仅弹窗。

### 8.3 用户端提交入口

至少提供以下入口：

1. **答案级反馈**：每条助手回答下方有「反馈」按钮，点击后自动关联该条问答。
2. **全局疑难提交**：问答页顶部或输入框附近有「疑难提交」按钮，可提交没有明确关联答案的问题。
3. **无答案引导（可选）**：系统回答「未找到相关内容」或没有引用时，提示用户提交反馈。

### 8.4 反馈表单字段

| 字段 | 必填 | 类型/长度 | 说明 |
| --- | --- | --- | --- |
| 反馈类型 | 是 | 枚举 | 答案错误、引用错误/缺失、回答不完整、知识库无相关内容、制度过期、其他 |
| 问题描述 | 是 | 10–1000 字 | 具体说明哪里有问题 |
| 期望答案/补充说明 | 否 | 0–1000 字 | 用户认为正确的答案或补充信息 |
| 联系方式 | 否 | 0–100 字 | 默认带入账号；可填写手机号/邮箱便于回访 |
| 关联问题 | 自动 | 只读 | 从消息 ID 读取，不由用户编辑 |
| 系统答案 | 自动 | 只读 | 保存快照，不由用户编辑 |
| 引用列表 | 自动 | 只读 | 文件名、页码/条款、命中片段 |
| 知识库/策略 | 自动 | 只读 | 当时使用的知识库与策略 |
| 会话/消息 ID | 自动 | 只读 | 用于管理员定位原始记录 |
| 截图附件 | 否 | 1 张，≤5MB | 可选增强，不作为本期硬性验收指标 |

### 8.5 自动快照要求

用户点击反馈时，前端只提交：

- `message_id` / `conversation_id`（如有关联）
- 反馈类型
- 问题描述
- 期望答案/补充说明
- 联系方式
- 可选的附件

后端根据 `message_id` 和当前用户身份：

1. 校验该消息属于当前用户，且该消息是助手回答。
2. 读取原问题、答案、引用、知识库、策略、时间等字段。
3. 生成不可被客户端篡改的快照并保存到反馈表。
4. 返回工单号和提交时间。

如果消息不属于当前用户或不存在，返回 404，不泄露消息是否存在。

### 8.6 提交流程

1. 用户点击「反馈」或「疑难提交」。
2. 打开表单，自动带入上下文摘要；用户可以展开查看原问答。
3. 用户选择类型、填写描述，提交。
4. 前端做必填、长度、频率校验。
5. 后端再次校验，保存反馈，生成工单号，例如 `FB-20261112-0001`。
6. 前端提示「提交成功，工单号 XXX」，并引导查看「我的反馈」。
7. 反馈初始状态为「待处理」。

### 8.7 我的反馈

用户可以查看自己提交的反馈：

| 字段 | 说明 |
| --- | --- |
| 工单号 | 唯一编号 |
| 反馈类型 | 中文标签 |
| 问题摘要 | 原问题或用户描述的前若干字 |
| 提交时间 | 精确到分钟 |
| 当前状态 | 待处理 / 处理中 / 已解决 / 已驳回 |
| 管理员回复 | 有则展示，无则显示「暂无回复」 |
| 操作 | 查看详情；不提供修改已提交内容，避免与管理员看到的内容不一致 |

用户不能查看他人反馈；管理员不能通过用户端接口查看全部反馈。

### 8.8 防滥用与内容安全

- 必须登录后才能提交反馈。
- 单用户提交频率限制，例如每小时最多 10 条；超过返回 429。
- 同一用户对同一消息重复提交时，提示「该问题已反馈，请勿重复提交」；是否合并由实现决定。
- 问题描述、期望答案、联系方式做长度校验和 XSS 转义；Markdown 渲染必须禁用危险 HTML。
- 反馈内容不得直接拼接进 SQL、日志或邮件头。
- 附件如实现，必须校验 MIME、大小、扩展名，并存储在非公开目录。

## 九、管理端反馈处理需求

### 9.1 页面定位

管理端新增独立页面 `/admin/feedback`，作为用户反馈的唯一处理入口。页面必须让管理员在不切换系统的前提下完成：

- 看到有多少待处理反馈。
- 找到某条反馈对应的原始问答与引用。
- 判断问题类型并决定处理方式。
- 回复用户、标记解决或驳回。
- 跟踪处理历史。

### 9.2 页面结构

#### 9.2.1 顶部统计

| 指标 | 说明 |
| --- | --- |
| 待处理 | 状态为 pending 的数量 |
| 处理中 | 状态为 processing 的数量 |
| 今日新增 | 当天提交的反馈数量 |
| 今日已解决 | 当天办结的数量 |
| 总数（可选） | 全部反馈数量 |

统计支持按时间范围筛选；管理员登录后应能看到待处理数量，导航菜单显示角标。

#### 9.2.2 筛选与搜索

| 筛选项 | 说明 |
| --- | --- |
| 状态 | 待处理 / 处理中 / 已解决 / 已驳回 |
| 反馈类型 | 六类枚举 |
| 知识库 | 按关联知识库筛选 |
| 提交人 | 用户名/姓名模糊搜索 |
| 时间范围 | 提交时间起止 |
| 关键词 | 工单号、问题、描述、答案内容 |

#### 9.2.3 列表字段

| 列 | 说明 |
| --- | --- |
| 工单号 | 可点击进入详情 |
| 反馈类型 | 中文标签，带颜色 |
| 问题摘要 | 原问题或用户描述的前 50 字 |
| 提交人 | 用户名/姓名 |
| 知识库 | 关联知识库名称 |
| 策略 | 当时使用的策略 |
| 状态 | 待处理/处理中/已解决/已驳回 |
| 提交时间 | 精确到分钟 |
| 处理人 | 当前处理管理员 |
| 操作 | 查看、受理、回复、解决、驳回 |

列表必须分页，默认按提交时间倒序；支持每页 20/50/100 条。

#### 9.2.4 反馈详情

详情页/抽屉必须展示：

- 工单号、状态、提交时间、提交人、联系方式。
- 反馈类型、用户问题描述、期望答案。
- 原始用户问题、系统答案全文。
- 引用列表：文件名、页码/条款、命中片段。
- 使用的知识库、问答策略、模型（如记录）。
- 会话 ID、消息 ID、检索日志链接（如可用）。
- 处理时间线：谁在什么时间做了什么操作。
- 管理员内部备注（用户不可见）。
- 给用户的回复（用户可见）。

### 9.3 处理动作与状态流转

| 当前状态 | 动作 | 目标状态 | 要求 |
| --- | --- | --- | --- |
| 待处理 | 受理 | 处理中 | 记录处理人 |
| 待处理 | 直接解决 | 已解决 | 必须填写回复或处理说明 |
| 待处理 | 驳回 | 已驳回 | 必须填写驳回原因 |
| 处理中 | 回复并解决 | 已解决 | 填写用户可见回复 |
| 处理中 | 驳回 | 已驳回 | 必须填写驳回原因 |
| 已解决/已驳回 | 重新打开（可选） | 处理中 | 仅管理员，记录原因 |

要求：

- 所有状态变更必须记录操作人、时间、前后状态、备注。
- 驳回必须填写原因，不能空原因驳回。
- 解决时建议填写用户可见回复；至少要有处理说明。
- 管理员可以认领/受理反馈，默认处理人为当前管理员。
- 管理员可以添加内部备注，内部备注不得返回给用户端。
- 支持从详情跳转到知识库页面处理文档问题；跳转时带上知识库/文档上下文（如现有页面支持）。
- 反馈处理不直接修改知识库内容；知识库更新仍走原有入库流程。

### 9.4 状态定义

| 状态 | 标识 | 含义 | 用户可见 |
| --- | --- | --- | --- |
| 待处理 | `pending` | 已提交，尚未受理 | 是 |
| 处理中 | `processing` | 管理员已受理，正在核实/处理 | 是 |
| 已解决 | `resolved` | 已处理并给出回复 | 是 |
| 已驳回 | `rejected` | 经核实无需处理/无法处理，附原因 | 是 |

### 9.5 通知与提醒

- 管理端导航「反馈处理」显示待处理数量角标。
- 管理员进入页面或刷新时更新统计；本阶段不要求 WebSocket 实时推送。
- 用户端在「我的反馈」中查看状态和管理员回复；本阶段不要求邮件/短信通知。
- 如后续接入企业微信/钉钉，可在状态变更时发送通知。

### 9.6 权限与隐私

- 只有 `admin` 可以访问反馈处理页面和接口。
- 普通用户只能查看自己的反馈，不能通过 ID 遍历他人反馈。
- 反馈详情中的问答快照仅用于处理反馈，管理员不得批量导出或用于其他目的。
- 反馈内容可能包含个人信息，日志中应脱敏；附件访问需要鉴权。
- 建议设置反馈数据保留期限（如 2 年），到期归档或匿名化；本阶段可先不做自动清理，但需在部署文档中注明。

## 十、数据模型建议

以下为逻辑模型，具体字段类型以现有 ORM 风格为准；新增表通过 Alembic 迁移创建。

### 10.1 用户表 `users`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BigInteger PK | 用户 ID |
| `username` | String(64) unique | 登录名 |
| `password_hash` | String(255) | 密码哈希 |
| `display_name` | String(100) | 姓名/显示名 |
| `role` | String(20) / Enum | `admin` / `user` |
| `department` | String(100) nullable | 部门，预留 |
| `status` | String(20) / Enum | `active` / `disabled` |
| `must_change_password` | Boolean | 首次登录/重置后强制改密 |
| `created_at` | DateTime | 创建时间 |
| `updated_at` | DateTime | 更新时间 |
| `last_login_at` | DateTime nullable | 最近登录时间 |

### 10.2 会话/令牌表 `auth_sessions`（可选）

如使用服务端 Session 或需要撤销 JWT，建议增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BigInteger PK | 会话 ID |
| `user_id` | BigInteger FK | 用户 |
| `token_hash` / `jti` | String | 令牌标识，不存明文令牌 |
| `expires_at` | DateTime | 过期时间 |
| `revoked_at` | DateTime nullable | 撤销时间 |
| `created_at` | DateTime | 创建时间 |
| `user_agent` | String(255) nullable | 客户端信息 |
| `ip` | String(64) nullable | 登录 IP |

### 10.3 反馈表 `feedback`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BigInteger PK | 主键 |
| `ticket_no` | String(32) unique | 工单号 |
| `user_id` | BigInteger FK | 提交人 |

## 十二、验收标准

### 12.1 认证与会话

- [ ] 未登录访问任意业务页面，跳转登录页；未携带凭证调用业务接口，返回 401。
- [ ] 管理员登录后进入管理端，侧边栏展示全部管理页面。
- [ ] 普通用户登录后进入用户端问答页，页面不出现管理端菜单和管理功能。
- [ ] 管理员可以使用同一账号登录用户端；用户端提供返回管理端入口。
- [ ] 普通用户尝试登录管理端或访问管理端路由，被拒绝并跳转用户端/登录页。
- [ ] 退出登录后，旧凭证失效；再次访问业务接口返回 401。
- [ ] 被禁用用户不能登录；已登录用户被禁用后下一次请求失效。
- [ ] 连续登录失败触发限流；错误提示不区分账号不存在与密码错误。
- [ ] 数据库中的密码为哈希；日志中无明文密码、完整令牌。
- [ ] 首次登录/重置密码后强制修改密码。

### 12.2 权限分配

- [ ] 管理员可以创建普通用户、分配角色、禁用账号、重置密码。
- [ ] 普通用户不能访问 `/api/v1/admin/**`，返回 403。
- [ ] 普通用户不能创建/删除知识库，不能上传/入库/删除文档。
- [ ] 普通用户不能选择或切换模型；请求中携带 `model` 参数不生效或被拒绝。
- [ ] 普通用户不能修改全局检索策略；只能选择已开放的策略预设。
- [ ] 普通用户不能查看日志、用户列表、他人反馈。
- [ ] 普通用户只能读取、删除自己的会话；访问他人会话返回 404/403。
- [ ] 管理员不能禁用/删除自己；不能移除最后一个管理员。

### 12.3 管理端

- [ ] 管理端原有问答、知识库、检索策略、日志功能在登录后可用，行为不回归。
- [ ] 管理端可以选择模型、查看检索详情、使用深度问答。
- [ ] 管理端可以管理策略预设，并设置是否对用户开放。
- [ ] 管理端反馈处理页面可打开，统计、筛选、列表、详情正常。
- [ ] 管理端用户管理页面可完成创建、改角色、禁用、重置密码。

### 12.4 用户端问答

- [ ] 用户可以选择已发布知识库并提问，获得流式回答。
- [ ] 回答展示 `[n]` 引用；引用卡片可查看文件名、页码/条款、命中片段。
- [ ] 用户可以新建、切换、删除自己的会话；刷新后历史仍可查看。
- [ ] 用户可以选择不同问答策略；回答中展示实际使用的策略；切换后检索结果/详情有对应变化。
- [ ] 用户端不出现模型选择、知识库管理、文档入库、检索策略配置、日志、用户管理、反馈处理入口。
- [ ] 用户端无可用知识库、无引用、接口异常时，有明确空态/错误提示。

### 12.5 反馈闭环

- [ ] 用户在答案下点击「反馈」，表单自动带入问题、答案、引用、策略、知识库。
- [ ] 用户填写类型和描述后提交成功，返回唯一工单号，状态为「待处理」。
- [ ] 管理端反馈列表出现该工单；顶部待处理统计增加；导航角标增加。
- [ ] 管理端可按状态、类型、知识库、提交人、时间、关键词筛选。
- [ ] 管理端详情展示完整问答快照、引用、策略、提交人、联系方式。
- [ ] 管理员可以受理、回复并解决、驳回；驳回必须填写原因。
- [ ] 状态变更后，用户「我的反馈」能看到最新状态和管理员回复。
- [ ] 用户不能查看他人反馈；管理员不能通过用户端接口查看全部反馈。
- [ ] 客户端篡改问题/答案文本不影响后端保存的快照。
- [ ] 未登录不能提交反馈；超长、空内容、超频提交被拒绝；重复提交有提示。
- [ ] 反馈内容 XSS 被转义，附件（如实现）不能直接公开访问。

### 12.6 安全与回归

- [ ] 除登录、健康检查外，所有业务接口默认要求认证。
- [ ] CORS 仅允许配置的前端来源；生产环境关闭不必要的调试接口。
- [ ] 管理员关键操作有审计记录：登录、创建用户、改角色、禁用、重置密码、反馈状态变更。
- [ ] Alembic 迁移可正常升级/回滚；历史会话迁移不丢失。
- [ ] 初始化管理员脚本可重复执行且不会重复创建/重置已有管理员密码。
- [ ] 管理端问答与检索质量较改造前无明显回归。
- [ ] 前端构建通过；后端单元/接口测试通过；关键权限用例有自动化测试。

## 十三、非功能要求

| 维度 | 要求 |
| --- | --- |

| 部署 | 双前端可独立构建/部署；共享后端；提供初始化管理员与迁移脚本；提供健康检查 |
