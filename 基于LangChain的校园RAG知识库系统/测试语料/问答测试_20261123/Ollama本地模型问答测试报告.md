## 摘要

本次测试对校园版知识库系统的**快速问答链路**（混合检索 + Rerank 精排 + 本地 `qwen3:8b` 生成）进行了 100 道题的端到端功能测试，题库覆盖两个知识库、三类题型（口语泛化 / 多跳推理 / 规范表述）。

**核心结论：**

- **总体准确率 82.0%**，其中 KB3（学生管理规定）达到 **97.0%**，KB4（绩效工资与成果奖励制度）仅 **67.0%**。
- **准确率差异几乎全部来自 KB4 的召回问题**，而非生成模型能力问题。KB3 与 KB4 共用同一条检索链路和同一个生成模型，KB3 接近满分说明模型本身能力正常。
- KB4 的 19 道失败题中，15 道直接指向 doc6《高质量发展成果专项奖励办法》的**入库解析缺陷**：PDF 硬换行拆断关键词、表格拆分丢失数字、带条号问法在 doc5/doc6 间产生歧义。
- 单题平均耗时 **28.8 秒**（检索 12.3s + 生成 16.5s），100 题总耗时约 **47.5 分钟**，符合此前 1 小时内的估算。

## 一、测试概述

### 1.1 测试目标

验证系统在真实场景下的问答质量，量化回答准确率，并定位召回链路的数据质量问题，为后续修复与正式上线提供依据。

### 1.2 测试范围

- **链路范围**：仅快速问答（单轮管道：意图 → 混合检索 → Rerank 精排 → LLM 生成），不涉及深度问答的 Agent 多轮决策。
- **知识库范围**：KB3「学生管理规定」、KB4「绩效工资与成果奖励制度」两个知识库。
- **模型范围**：本地 Ollama `qwen3:8b`（GPU 推理）。API 模型（deepseek-chat）同题库的对照测试另行执行。

## 三、测试方法与流程

### 3.1 题库设计

题库共 **100 道唯一题目**，每个知识库各 50 道，题型按 50 / 25 / 25 配比：

| 题型 | 定义 | 题量 |
| --- | --- | --- |
| 口语泛化 | 贴近师生日常表达的口语化提问，考察语义理解 | 50 |
| 多跳推理 | 需跨 2 个以上条款/文档才能完整作答 | 25 |
| 规范表述 | 规范条文的直接查询，考察精确召回 | 25 |

每题包含：问题、参考答案、证据（文档 ID + PDF 页码 + 条款号 + 原文摘录）、关键词、难度（easy/medium/hard）。

### 3.2 执行流程

1. 先用 10 道题做预热（不计入结果），确认链路正常并预估耗时。
2. 全量 100 题按题号顺序逐题调用快速问答接口，记录 `retrieval_s`、`first_token_s`、`generation_s`、`total_s`、`answer_chars`、`citation_ids` 等字段。
3. 流式输出逐字落盘，最终答案完整保存。

### 3.3 评分方法

- **裁判**：由 AI（DeepSeek 模型）逐题对照「参考答案 + 证据原文」对模型答案进行四档评分。
- **评分档位**：

| 档位 | 分值 | 判定标准 |
| --- | --- | --- |
| 正确 | 1.0 | 主结论正确，关键数字 / 条件 / 时限完整 |
| 部分正确 | 0.5 | 主结论对，但漏条件、个别数字错、多跳只答对一跳 |
| 错误 | 0.0 | 结论错、编造、答非所问 |
| 拒答 | 0.0 | 明确表示"资料不足"（资料实际有答案时记为 0，单独标注为召回失败型拒答） |

- 评分依据题库中已逐字核对的参考答案与证据原文，未引入模型主观判断。

## 五、问题分析

### 5.1 核心问题：doc6 入库解析缺陷导致 KB4 召回失败（占比最大）

KB4 的 19 道失败题中，**15 道直接指向 doc6《高质量发展成果专项奖励办法》**。根因有三层，均在**入库解析阶段**，而非检索算法或生成模型：

**（1）PDF 硬换行拆断关键短语**

原文"全额追回"被排版成两行，抽取后夹入换行符，索引中不存在连续的"全额追回"：

```
3.对存在学术不端、弄虚作假等行为的，一经查实，全额追
回已发放奖励，取消相关责任人三年内申报资格
```

导致 kb4-formal-009 问"全额追回"时精确匹配落空，向量语义也受损。

**（2）表格拆分丢失数字**

doc6 第四条奖励金额是表格，表格头与具体行被切成不同 chunk，"50 万元"数字与单位分离，连写的"50万元"在索引中 0 命中，导致 kb4-formal-005、kb4-oral-013/014 等金额题全部失败。

**（3）带条号问法在 doc5/doc6 间产生歧义**

doc5 与 doc6 大量重复使用"第七条""第八条""第九条"等条号。问"第九条奖励经费""第七条不重复奖励"时，向量检索被 doc5 的同条号条款干扰，doc6 的正确分块进不了 top 20。

**验证依据**：KB3 与 KB4 共用同一检索链路和同一生成模型，KB3 达 97% 而 KB4 仅 67%，差异可归因于 KB4 的 doc6 数据质量，而非模型能力。

### 5.2 次级问题：doc5 计分表格分值混淆（3 题）

kb4-hop-007/008/009 三道题，模型检索到了 doc5 计分办法表格中**错误档位的分值**（如把省部级重点项目 400 分误作 20 分、把 B1 类 300 分误作 600 分）。这是表格跨行/跨类型对齐错误，同样属于入库解析的表格处理缺陷。

### 5.3 轻微问题：个别理解与表述错误（1 题 + 3 题部分正确）

- kb4-oral-019 把"单个项目配套总额不超过 20 万"误读为"无封顶"。
- KB3 的 3 题部分正确（kb3-hop-001、kb3-hop-012、kb3-oral-022）属模型对边界条件的表述不精确，与召回无关。

### 5.4 引用标注瑕疵

个别题（kb3-hop-002、kb3-oral-004）的"依据文件名"张冠李戴（如把《全日制本科生转专业管理办法》写成《本科生学业预警管理办法》），主体答案正确，但引用溯源存在瑕疵。

## 六、结论与建议

### 6.1 结论

1. **模型与检索链路本身可用**：KB3 达 97%，证明混合检索 + 精排 + `qwen3:8b` 在数据质量良好的知识库上表现优秀。
2. **瓶颈在入库解析的数据质量**：KB4 的低分几乎全部由 doc6 的 PDF 硬换行、表格拆分、条号歧义导致，属于**检索前数据质量问题**。
3. **耗时达标**：单题平均 28.8 秒，100 题约 47.5 分钟，本地 CPU/GPU 混合推理下可接受。

### 6.2 建议（按优先级）

1. **修复入库解析（高优先）**：分块前将 PDF 硬换行归一化、表格结构化重排（数字与单位合并、行对齐补全），消除"全额追回""50万元"等被拆断的短语。
2. **检索侧条号消歧（中优先）**：对"第 X 条"的规范问法做文档消歧，或在召回阶段对条号关键词加权。
3. **题目侧优化（低优先）**：规范表述题尽量用具体关键词而非纯条号，避免跨文档歧义。
4. **对照测试**：修复后用同一题库跑 API 模型对照，验证两模型在修复后的数据上的真实差异。

## 七、修复与复测（2026-11-24）

- 题库、题量、顺序与初测完全一致，100 道题。

### 7.5 剩余问题与归因

**（1）doc5 与 doc6 附件内容重复（多跳下降主因）**

doc6 合订本内含"附件 1 绩效工资实施方案补充意见""附件 5 教学研究业绩计分办法"，与 doc5 文本完全相同。检索时会同时返回两份副本：

- kb4-oral-010 的 top1 是 doc5，top2 是 doc6，正文一致，模型反而拒答；
- kb4-oral-016 的正确分块在 doc5 第 71 页，但 doc6 的重复表格排到第 1 位，引用文档出现偏差；
- 计分表重复且解析质量不一致，是 hop-001/002/009 数值冲突、多跳从 68% 降到 62% 的主要原因。

**（2）单列"表格"误判拆断句子**

部分正文被 pdfplumber 识别为单列表格，输出成：

```
原则上不低
| --- |
于 32课时/年
```

答案仍能答对，但句子被拆断，影响可读性与后续抽取。

**（3）生成侧拒答与漏答（3 题）**

- kb4-oral-010：证据已在 top5 内，模型仍称"未找到规定"；
- kb4-formal-012：模型拒答，未给出参考答案中的区分规则；
- kb4-oral-016：5000 分已出现在第 3 条上下文中，模型未答出。

**（4）"奖金"与"计分分值"两套口径混淆（3 题）**

oral-013 应回答 25 万，模型答 2000 分；oral-015 应回答 200 万/80 万，模型答 25 万/10 万；hop-002 计分算成 120 分（应 1200 分）。同一附件同时存在金额表和计分表，重复副本加剧了混淆。

**（5）本地模型单次评分的波动**

KB3 索引未做任何变更，仍有 6 题从 1.0 降到 0.5，说明 `qwen3:8b` 在 temperature=0.1 下单次运行存在约 ±3-5 分的波动，单次总分不宜作为唯一结论。

### 7.6 结论

1. **修复目标基本达成**：KB4 从 61% 提升到 72%，规范表述从 72% 提升到 90%，doc6 相关拒答全部消除，总体从 73% 提升到 79%。
2. **权限问题是首要根因**：`admin_only` 对管理员不可见，导致 doc6 此前完全无法检索；解析缺陷是第二层原因。
3. **多跳仍是短板**：证据能召回，但精排与跨块聚合能力不足，叠加 doc5/doc6 重复附件，导致该维度下降 6 分。
4. **下一轮优先级**：先对 doc5/doc6 重复附件去重或指定唯一权威副本，再修单列表格误判，最后针对多跳做专项；评估时建议同一题跑 3 次取均值，降低单次波动。
