# 校园 RAG 问答测试题库（200 条模板）

## 1. 口径说明

- 唯一题 100 道，同一道题分别交给 **API 模型** 和 **本地 Ollama** 各跑一次，共 **200 条测试记录**。
- 题目、参考答案、证据位置均已填好；评分、引用准确、耗时、备注列留空，测试时填写。
- 所有答案均来自三个 PDF 的原文，证据列给出文档 ID、PDF 页码、条款号和原文摘录，可逐条回查。

## 2. 覆盖范围

| 知识库 | kb_id | 文档 | 题量 | 口语泛化 | 多跳推理 | 规范表述 |
| --- | --- | --- | --- | --- | --- | --- |
| 学生管理规定 | 3 | doc3 测试集.pdf（215 页） | 50 | 25 | 13 | 12 |
| 绩效工资与成果奖励制度 | 4 | doc5 1.pdf（76 页）+ doc6 2.pdf（88 页） | 50 | 25 | 12 | 13 |
| 合计 | - | - | 100 | 50 | 25 | 25 |

难度分布：easy 30、medium 40、hard 30。多跳题证据数 2-3 条，KB4 中 5 道为跨 doc5/doc6 多跳。

## 3. 文件说明

| 文件 | 用途 |
| --- | --- |
| `校园RAG问答测试_200条模板.csv` | 200 条测试记录，UTF-8 BOM，可直接用 Excel 打开填写 |
| `qa_kb3.jsonl` | KB3 的 50 道题，供项目自带评估命令使用 |
| `qa_kb4.jsonl` | KB4 的 50 道题，供项目自带评估命令使用 |
| `results_*.jsonl` | 各轮原始回答，含模型标签、引用数、首字延迟与总耗时 |
| `scores_*.json`、`评分明细_*.csv` | 各轮评分汇总与逐题明细（判定说明、参考答案、模型答案对照） |
| `recall_after_fix.json`、`recall_after_dedup_kb4.json` | 检索级验证：证据是否进入候选集与最终 top5 |
| `dup_analysis.json` | doc5/doc6 重复附件量化数据 |
| `kb4_baseline_diagnosis.json`、`pilot10_ollama_timing.json` | KB4 基线诊断与 10 题耗时抽样 |
| `scripts/run_qa.py` | 批量跑题脚本，切换模型来源后可直接复跑 |
| `scripts/score_answers.py` | 按人工复核结果汇总评分，输出 JSON 与 CSV |

CSV 中同一题号出现两次，`模型` 列分别为 `API` 和 `Ollama`；`深度复测` 列标记为“是”的 25 道多跳题，在快速问答之外再用深度问答复测，复测结果不计入这 200 条。

## 4. 检索与问答配置

- 检索策略：**精准检索**（`strategy_id=1`，混合检索 + 精排，向量/BM25 各 0.5，RRF k=60，rerank 开启）。
- 问答模式：主测试统一 **快速问答**。
- 测试身份：统一使用 `--role admin`。KB4 的 doc6 是 `admin_only`，doc5 是部门可见（department_id=1），只有管理员身份能同时覆盖两篇文档；KB3 的 doc3 为公开文档。
- 每题独立会话，不携带历史，关闭语义缓存，保证两个模型输入一致。

## 5. 评估命令

在 `基于LangChain的校园RAG知识库系统/backend` 目录下执行。

```powershell
# 校验题库
.\.venv\Scripts\python.exe -m src.evaluation.cli validate --testset "..\测试语料\问答测试_20261123\qa_kb3.jsonl"
.\.venv\Scripts\python.exe -m src.evaluation.cli validate --testset "..\测试语料\问答测试_20261123\qa_kb4.jsonl"

# 检索评估
.\.venv\Scripts\python.exe -m src.evaluation.cli retrieval --testset "..\测试语料\问答测试_20261123\qa_kb3.jsonl" --kb-id 3 --strategy-id 1 --role admin --top-k 10 --output "..\测试语料\问答测试_20261123\retrieval_kb3.json"
.\.venv\Scripts\python.exe -m src.evaluation.cli retrieval --testset "..\测试语料\问答测试_20261123\qa_kb4.jsonl" --kb-id 4 --strategy-id 1 --role admin --department-id 1 --top-k 10 --output "..\测试语料\问答测试_20261123\retrieval_kb4.json"

# 生成评估（当前评估命令使用数据库中的模型配置，跑 API 与 Ollama 前先在管理端切换模型）
.\.venv\Scripts\python.exe -m src.evaluation.cli generation --testset "..\测试语料\问答测试_20261123\qa_kb3.jsonl" --kb-id 3 --strategy-id 1 --role admin --output "..\测试语料\问答测试_20261123\generation_kb3.json"
.\.venv\Scripts\python.exe -m src.evaluation.cli generation --testset "..\测试语料\问答测试_20261123\qa_kb4.jsonl" --kb-id 4 --strategy-id 1 --role admin --department-id 1 --output "..\测试语料\问答测试_20261123\generation_kb4.json"
```

`validate` 会提示“低于阶段二要求的 300 条”，这是项目的旧阈值提示，本次按每库 50 道设计，不影响使用。

## 6. 评分与记录

| 列 | 填写方式 |
| --- | --- |
| 评分 | `1` 完全正确；`0.5` 部分正确；`0` 错误；`拒答` 明确说明资料不足 |
| 引用准确 | `是` / `否`，引用编号能否对到证据文档、条号和页码 |
| 首字延迟ms | 从发起提问到第一个字返回的毫秒数 |
| 总耗时ms | 整轮回答完成的总毫秒数 |
| 备注 | 记录错因：检索未命中、证据不足、生成错误、引用错误等 |

裁判建议统一用 API 模型，不要用本地 8B 模型自评。现有生成评估命令的裁判与生成共用同一份模型配置，若要用 API 裁判 Ollama 的答案，需要在跑完后人工复核，或另行调整评估参数。

## 7. 结果概览

| 轮次 | 模型与索引状态 | 总体 | KB3 | KB4 |

| 基线 | qwen3:8b，修复前 | 73.0% | 85.0% | 61.0% |

## 8. 使用约定

- 本目录除原始 PDF 外均可提交，PDF 因含文档提供方内部资料已列入 `.gitignore`。
- 题目只依赖各自知识库，不能跨库回答；KB3 题目只用 doc3，KB4 题目只用 doc5/doc6。
- 测试过程中对解析、切分与检索代码做过修复，修复项与对应收益见 `评分与模型选型报告.md` 第四节。
