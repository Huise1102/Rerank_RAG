# 阶段二实施计划：文档治理、权限过滤与可信回答

## 一、背景与目标

阶段一已完成登录鉴权、双前端、混合检索问答、引用折叠、反馈与审计。阶段二按 `docs/阶段二.md` 推进 M1 至 M9，使答案只来自「当前有效、用户有权查看、可回溯到具体条款」的文档，并用黄金测试集与回归报告证明治理改造未降低质量。

已确认的默认决策：

- 角色为 `admin / dept_admin / staff / student`，阶段一 `user` 迁移为 `student`。
- 首期部门为「教务处」与「待分配」；`admin_only` 文档不进入问答索引。
- 可见性为 `public / department / admin_only`；检索只召回 `public` 与 `department`。
- 版本号使用可读字符串；支持未来生效日期，生效前不召回。
- 转办时限按 1 个工作日内首响、3 个工作日内办结。
- 真实 400 条黄金测试集由教务处提供，本次交付脱敏样例、生成与校验工具及评估框架。

## 二、总体设计

### 2.1 数据模型（M1、M3）

修改 `backend/src/db/models.py`：

- 新增 `Department`：`name`、`code`、`parent_id`、`contact`、`status`。
- `User` 增加 `department_id`，角色扩展为四级，保留 `department` 字符串用于展示。
- `Document` 扩展为逻辑文档：`title`、`doc_no`、`department_id`、`visibility`、`owner_user_id`、`current_version_id`、`review_due_date`、`doc_status`；保留原 `status`、`filename`、`stored_path` 等字段作为当前版本快照，避免阶段一接口与前端断裂。
- 新增 `DocumentVersion`：版本号、文件路径、哈希、处理状态、生命周期状态、生效日期、废止时间、替代版本、分块数、发布人、发布时间；用 MySQL 生成列 `published_doc_id` 加唯一索引，保证同一文档最多一个已发布且未废止版本。
- `Feedback` 增加 `kind`、`assigned_department_id`、`assigned_user_id`、`transfer_reason`、`first_response_at`；状态扩展 `replied`。
- `RetrievalLog` 增加 `role`、`department_id`、`visibility_scope`、`document_versions`。
- 新增 `EvaluationReport` 保存评估报告 JSON 与摘要。

新增 `backend/alembic/versions/0002_stage2_governance.py`：

- 显式 `ALTER TABLE`，不依赖 `create_all`。
- 创建部门表并写入「教务处（JWC）」「待分配（PENDING）」。
- `users.role` 的 `user` 统一更新为 `student`；历史部门无法匹配的进入「待分配」。
- 为已有文档回填一条 `v1` 版本，生命周期 `published`、处理状态 `completed`、生效日期为迁移当天、可见性 `public`，并回填 `current_version_id`。
- 提供完整 `downgrade`，可回滚角色、列与新表。

初始化脚本 `backend/scripts/init_db.py` 增加部门种子；`init_admin.py` 保持管理员不变。

### 2.2 检索权限（M2）

新增 `backend/src/retrieval/scope.py`：

- `RetrievalScope`：`user_id`、`role`、`department_id`、`now`、`allow_public`、`allow_department`。
- `build_chroma_filter(scope, kb_id)`：统一生成 metadata `where`，包含知识库、生命周期、生效日期、废止时间、可见性、部门。
- `metadata_allowed(metadata, scope)`：BM25 掩码使用同一套规则，确保两路过滤口径一致。
- 管理员问答只放宽部门限制，不跳过版本与时效过滤。

改写 `backend/src/retrieval/bm25.py`：

- 使用 `rank_bm25` 与 jieba 分词自建索引，支持全量打分。
- 先用 `metadata_allowed` 生成 NumPy 掩码，将无权或过期块分数置零，再取 Top-k；禁止先取 Top-k 后过滤。
- 保留 pickle 持久化与失效缓存，新增索引统计接口。

修改 `backend/src/retrieval/retrievers.py`：

- `build_retriever(kb_id, preset, scope)`；向量侧使用 `build_chroma_filter`，BM25 侧使用掩码检索。
- 融合仍用 RRF，精排仍用 CrossEncoder，且只处理已过滤候选。
- 检索详情增加 `role`、`department_id`、`visibility_scope`。

### 2.3 文档服务与生命周期（M3、M4）

新增 `backend/src/services/document_service.py`：

- 创建文档与草稿版本、上传新版本、列表与详情（部门管理员仅本部门）。
- 发布：事务内校验处理完成、分块数大于 0、可见性已填；旧版本置为 `repealed` 并写 `superseded_by_version_id`，切换 `current_version_id`，写审计。
- 废止、归档、回滚；回滚仅管理员。
- 预览与下载 ACL：越权统一 404。

新增 `backend/src/services/ingest_service.py`：

- `parse_and_index_version`：解析、结构化分块、写入带完整 ACL metadata 的向量块；按 `document_id` 删除旧块后写入；从 Chroma 现有块重建该知识库 BM25，不重新调用嵌入模型。
- `check_index_consistency`：比较数据库版本分块数、Chroma 条数、BM25 条数，返回明细。
- 全库重建只用于分块策略变更或管理员显式操作。

接口新增 `backend/src/api/routes/documents.py` 与 `departments.py`，路径遵循 `docs/阶段二.md` 第十三节；旧 `/kb/{id}/documents` 接口保留但内部转为新服务，避免阶段一前端立即失效。

### 2.4 结构化解析与分块（M5）

修改 `backend/src/ingest/loaders.py`：

- PDF 用 `pdfplumber` 提取页文本与表格；表格转为 Markdown 块，保留页码与表格序号。
- DOCX 用 `python-docx` 按正文顺序读取段落与表格。
- 解析失败保留文本并记录警告，不静默丢表。

修改 `backend/src/ingest/splitter.py`：

- 新增 `clause` 策略：识别 `第X章/节/条`，条文为主检索单元，章节作为父块；长条文二次切分并保留 `article_no`、`parent_chunk_id`。
- 表格块不切断，超长按行拆分并重复表头。
- 无法识别条款时自动回退 `recursive`，不伪造条款号。
- 生成稳定 `chunk_id`、`content_hash`，去除空块与重复块，写入 `parent_text`。
- 配置 `chunk_strategy`、`chunk_min_size`、`table_max_rows` 等参数。

### 2.5 引用、免责声明与预览（M6）

修改 `backend/src/generation/chain.py`：

- 上下文与引用增加文号、条款号、版本号、生效日期、责任部门、页码范围。
- 引用标签示例：`[1]《XX 管理办法》（2025 修订）第三十八条，第 12 页`。
- 导出固定免责声明常量。

修改 `backend/src/services/chat_service.py`：

- 从登录用户构造 `RetrievalScope`，不接收前端角色与部门。
- 无召回时拒答并返回 `transfer_required`；引用为空时同样提示转人工。
- 检索日志记录角色、部门、可见范围、命中版本。
- 上下文拼接优先使用 `parent_text` 回填父级条款。

前端：

- `Chat.vue` 引用卡片展示条款、版本、生效日期、部门；答案下固定免责声明；无引用时显示「转人工」。
- 新增 `api/document.js`；`Knowledge.vue` 增加上传元数据表单、文档详情抽屉、版本历史、发布/废止/解析/重建/预览操作。
- `AnswerContent.vue` 保持现有引用跳转能力。

### 2.6 黄金测试集与评估（M7）

新增 `backend/src/evaluation/`：

- `metrics.py`：Recall@k、MRR、nDCG、Hit、Precision。
- `judge.py`：忠实度与答案相关性裁判，JSON 解析与失败重试。
- `testset.py`：JSONL 校验、类别统计、脱敏检查。
- `retrieval_eval.py`、`generation_eval.py`、`cli.py`。
- 评估调用本项目检索与生成服务并携带 `RetrievalScope`，不绕过 ACL。

数据与接口：

- `backend/tests/fixtures/evaluation_sample.jsonl` 放脱敏样例。
- 新增 `GET/POST /admin/evaluation/*` 与 `Evaluation.vue` 报告页。
- 报告保存 Markdown + JSON；真实测试集目录不提交仓库。

### 2.7 人工转接（M8）

修改 `feedback` 路由与服务：

- 新增 `POST /feedback/transfer`，按消息 ID 由后端生成快照，分配知识库归属部门。
- 转办单编号 `TR-YYYYMMDD-0001`，状态支持 `pending / processing / replied / resolved / rejected`。
- 管理端按角色与部门过滤；受理、回复、办结、退回写审计。
- 用户端「我的反馈」展示转办状态与回复。

### 2.8 部署与验收（M9）

- `backend/scripts/backup.ps1`：备份 MySQL 与原始文档，输出恢复说明。
- 健康检查增加数据库、存储、索引一致性、模型预热状态。
- 更新 `README.md` 与新增 `docs/阶段二实施记录.md`、`docs/evaluation/regression_v2.md`。
- 逐项对照阶段二验收清单，记录通过项与未验证项。

## 四、实施顺序

1. M1：模型、迁移、部门种子、角色迁移、用户页角色与部门。

3. M3：文档与版本服务、发布废止归档、预览 ACL。
4. M4：单版本增量索引、BM25 无嵌入重建、一致性检查。
5. M5：表格解析、条款切分、父子块与入库报告。
6. M6：引用字段、免责声明、转人工提示、前端展示。
7. M7：评估模块、样例测试集、管理端报告页。
8. M8：转办接口、状态流转、管理端与用户端页面。
9. M9：备份脚本、健康检查、回归报告与验收清单。

每个里程碑完成后执行：后端语法检查、`pytest tests -q`、Alembic 升级与回滚、前端构建、相关接口冒烟、注释检查、更新 README 与实施记录。

## 五、验证方式

- 迁移：`backend\.venv\Scripts\python.exe -m alembic upgrade head`，再 `downgrade 0001_initial`，最后重新升级。
- 单元测试：`backend\.venv\Scripts\python.exe -m pytest tests -q`。
- 启动：`backend\.venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8004`。
- 双前端构建：`npm run build:admin`、`npm run build:user`。
- ACL 冒烟：分别用 `admin`、`staff`、`student` 账号检索同一知识库，确认 `department` 文档仅本部门教职工可见，`admin_only` 不召回。
- 生命周期冒烟：发布新版本后旧版本召回为 0；未来生效版本生效前不召回；废止文档不召回；回滚可恢复。
- 解析冒烟：用含表格的制度 PDF/DOCX 验证表格块、条款号、父块回填。
- 评估：`python -m src.evaluation.cli retrieval --testset tests/fixtures/evaluation_sample.jsonl`，确认指标可复现。
- 转办：用户从无引用回答发起转办，部门管理员受理、回复、办结，用户可见状态。

## 六、明确不在本次验证范围

- 教务处真实 400 条黄金测试集的标注质量与规模。
- 学校 CAS、企业微信、钉钉协议对接。
- 邮件、短信等外部通知。
- 生产 GPU 环境下的精排压测与 P95 目标。
- 多部门全面上线与跨部门联合检索。
