- `backend/scripts/init_db.py` 新增部门种子数据。

### 2.2 M2 检索层权限过滤

- `backend/src/retrieval/scope.py` 新增 `RetrievalScope`，从登录用户解析角色、部门与当前时间，不接受前端传入的角色或部门。
- `build_chroma_filter` 生成向量召回过滤条件，包含 `lifecycle_status`、`effective_ts`、`repealed_ts`、`visibility`、`department_id`。
- `metadata_allowed` 提供与向量过滤一致的 BM25 掩码判断，并兼容阶段一的字符串日期字段。
- `backend/src/retrieval/bm25.py` 改为 jieba 分词加 `BM25Okapi`，先对全量语料打分，再用 NumPy 掩码过滤，最后取 Top-k，避免先取候选再裁剪。
- `backend/src/retrieval/retrievers.py` 增加 `ScopedBM25Retriever`，并把 `scope` 传给向量检索器。
- 管理员在正常问答中可检索全部部门的 `public` 与 `department` 文档，`admin_only` 不在任何角色的检索范围内。

### 2.3 M3 文档与版本生命周期

- `backend/src/services/document_service.py` 提供文档与版本的权限判定、创建、追加版本、修改元数据、发布、废止、归档、回滚、删除与预览路径解析。
- 发布流程先校验归档状态、可见性、处理状态与索引一致性；分块数、向量数与 BM25 数不一致时返回 503，禁止切换当前版本。
- 发布流程在同一事务内把旧版本置为 `repealed` 并清空 `published_doc_id`，随后写入新版本，最后切换 `current_version_id`。
- `document_versions.published_doc_id` 上的唯一约束 `uq_document_versions_published` 保证同一逻辑文档最多一个当前发布版本。
- 发布、废止、回滚、归档、属性变更均写入审计日志。
- `backend/src/api/routes/documents.py` 提供文档与版本接口，部门管理员只能操作本部门文档，越权返回 404。

### 2.4 M4 单文档增量重建与一致性

- `backend/src/services/ingest_service.py` 以版本为单位删除旧块、写入新块，不触发全知识库重新嵌入。
- 每次写入同时刷新 Chroma 与 BM25；BM25 从 Chroma 现有分块重建，不调用嵌入模型。
- 版本记录保存 `chunk_count`、`table_count`、`clause_count` 与 `ingest_report`。
- `check_index_consistency` 比对数据库分块数、Chroma 分块数与 BM25 分块数。
- 删除文档或版本时同步清理两路索引。
- `rebuild_kb_with_versions` 只在分块策略变化或人工重建时使用，按当前发布版本重建整个知识库。

### 2.5 M5 结构化解析与分块

- `backend/src/ingest/loaders.py` 使用 pdfplumber 提取页文本与表格，使用 python-docx 按正文顺序读取段落与表格；表格统一转为 Markdown 文本，解析异常记录警告而不丢弃整表。
- `backend/src/ingest/splitter.py` 识别 `第X章`、`第X节`、`第X条`，以条为检索单元生成子块，并写入 `article_no`、`parent_text`、`parent_chunk_id`。
- 表格块不参与普通递归切分，超长表格按行拆分并在每段重复表头。
- 无条款结构的文档自动回退递归切分，不伪造条款号。
- 块编号格式为 `document_id:version_id:index:content_hash前8位`，同一版本内按 `content_hash` 去重。
- 块元数据包含 `chunk_id`、`document_id`、`version_id`、`source`、`page`、`page_end`、`department_id`、`visibility`、`lifecycle_status`、`effective_date`、`repealed_at`、`doc_no`、`doc_title`、`version_label`、`chunk_type`、`article_no`、`parent_chunk_id`。

### 2.6 M6 引用、免责声明与预览

- `backend/src/generation/chain.py` 增加统一免责声明与拒答文案，引用对象包含 `chunk_id`、`version_id`、`doc_title`、`doc_no`、`page_end`、`article_no`、`version_label`、`effective_date`、`department`、`label`、`text`、`preview_url`。
- 上下文拼接优先回填 `parent_text`，命中子块时带回所属条款上下文，引用页码仍指向子块页码。
- `backend/src/services/chat_service.py` 按登录用户构造检索范围；无召回时直接拒答并标记 `transfer_required`；检索日志写入角色、部门、可见范围与版本。

## 四、关键设计决策

### 4.1 日期过滤使用数值时间戳

Chroma 的 `where` 只接受数值比较，字符串日期会导致 `Expected where value to be a float or integer`。因此索引 metadata 同时写入 `effective_date` 与 `effective_ts`、`repealed_at` 与 `repealed_ts`：前者用于展示与引用，后者用于过滤。检索范围提供 `today_ts` 与 `now_ts`，保证两路召回口径一致。

### 4.2 权限过滤前置

向量召回在 Chroma 查询条件内过滤，BM25 在全量打分后按掩码过滤再取 Top-k。融合、精排、上下文拼接只接触有权候选，引用不会泄露无权文档的标题、文号或片段。

### 4.3 单当前版本

逻辑上由 `current_version_id` 指向当前版本，物理上由 `published_doc_id` 唯一约束兜底。发布时先废止旧版本并落库，再写入新版本，避免出现两个当前版本。

### 4.4 仅管理员文档不参与问答

`admin_only` 文档可以解析与发布，也保留索引以便管理端预览，但检索范围只包含 `public` 与 `department`，任何角色都不会在问答中召回该类文档，符合阶段二「不开放该类文档问答」的边界。后续开放时只需扩展检索范围，不需要重新解析。

### 4.5 转办复用反馈表

转办单不新建工单表，通过 `kind` 区分普通反馈与转人工，沿用阶段一状态与处理时间线，减少重复模型与页面。
