## 一、默认决策

与用户确认后采用以下默认值：

1. 企业入口只实现企业微信网页授权登录，不提供其它身份源；站内通知作为默认通知渠道，不接入外部消息发送。
2. 缓存启用精确缓存与语义缓存；语义缓存用本地嵌入模型编码问题，在 Redis 列表中做余弦相似度匹配，默认关闭，阈值默认 0.85，可在 0.75 到 1.0 之间调整。
3. 深度问答默认关闭，由系统管理员按知识库与角色白名单开启，最多三轮决策。
4. 存量知识库在迁移时统一回填为全校公开，避免阶段二学生问答能力回退；新建知识库默认部门内部。
5. 部门管理员可以管理归属本部门的知识库，包括系统管理员创建的本部门公开库，但不能创建公开库。
6. 精确缓存默认有效期 7 天，可配置 1 到 30 天；索引版本在知识库或文档检索范围变化时递增。

## 二、里程碑实施情况

### M1 多部门知识库治理

- 知识库新增可见性、归属部门、责任人、复核周期与索引版本字段；部门新增排序与联系方式。
- 新增 `GET /knowledge-bases`，按角色返回公开库与本部门库；`/kb` 作为管理列表，按部门范围过滤。
- 用户端选库由后端判定，越权访问返回 404；停用知识库与停用部门不再对用户展示。
- 部门管理员只能创建和维护本部门知识库，公开库仅系统管理员创建，公开库不得绑定部门。
- 知识库名称、状态、可见性、归属部门、分块策略变化时递增索引版本。

### M2 移动端 H5

- 在管理端与用户端之外新增第三个构建入口：`VITE_APP_MODE=mobile`，开发端口 5176，产物为 `dist/mobile`。
- 移动端使用独立路由与外壳，顶部为标题、通知与设置，底部为问答与我的反馈两个标签页，内容区高度按 `100dvh` 与安全区适配。
- 用户端复用同一套 Vue 工程，新增 768 像素断点、360 像素适配、安全区与 44 像素触控目标。
- 会话列表在移动端改为侧滑抽屉；引用详情改为底部抽屉；检索详情改为全屏覆盖。
- 增加停止生成、回到底部、窄屏表格横向滚动、错误提示与重试。
- 用户端构建产物不包含管理端路由，管理端保持 PC 布局；企业微信网页授权回调指向移动端 `/wecom/callback`。

### M3 热点问题缓存

- 新增 Redis 异步客户端与缓存服务，Redis 不可用时自动降级为未命中，不阻断问答。
- 缓存键包含知识库、策略、权限范围、索引版本与归一化问题哈希，禁止跨权限与跨版本命中。
- 命中后复核用户权限、文档归属、当前版本、版本状态与生效日期；任一不满足时删除缓存并回源。
- 只缓存快速问答的新会话首问成功答案；拒答、转办、深度问答、仅管理员文档不进入缓存。
- 文档发布、废止、归档、删除、可见性变化、知识库重建与启停时递增索引版本，旧键立即失效。
- 新增缓存设置、统计、清理与样本标记接口，管理端新增「热点缓存」页面。

### M4 深度问答

- 新增 `src/agent` 包，包含提示词、状态、工具与决策循环，最多三轮决策、三次检索，第三轮强制作答。
- 检索工具只调用阶段二的检索服务，权限、版本与生效日期过滤不另写一套。
- 新增深度问答设置接口与用户端能力探测接口，默认关闭，仅白名单知识库与角色可见入口。
- 用户端展示实时阶段状态与决策轨迹，回答与轨迹写入消息检索详情；异常时回退快速问答。
- 深度问答不写入缓存，失败回退也不写入缓存。

### M5 站内通知

- 新增通知表与服务，反馈受理、回复、办结、驳回与转办创建时写入站内通知。
- 文档复核状态变化与到期提醒通知责任人、部门管理员，缺少部门管理员时回落到系统管理员。
- 用户端顶部增加通知铃铛、未读数与全部已读，通知点击后跳转对应页面。
- 企业入口只保留企业微信：新增网页授权接口、一次性 state 校验、成员身份换取与同名账号自动绑定，移动端登录页按配置展示入口。

### M6 运营看板与知识缺口

- 新增看板接口，统计提问量、活跃用户、零引用率、转办率、反馈率、缓存命中率、P50、P95、待处理反馈、过期文档与未解决缺口。
- 支持按日期范围与部门过滤；管理员看全部，部门管理员只看本部门。
- 新增知识缺口表与扫描服务，汇总零引用、拒答、负反馈与转办问题，按归一化问题聚合，保留处理状态。
- 新增缺口列表、扫描、更新与 CSV 导出；导出带 BOM，Excel 可直接打开。
- 新增到期复核清单，支持确认继续有效、发起修订与废止；操作写审计并触发通知。

### M7 测试与回归

- 新增知识库可见性、缓存键隔离、深度问答轮数、看板口径、复核日期与深度问答开关测试。
- 迁移支持升降级；阶段一与阶段二用例保持通过。

## 六、运维说明

1. 缓存失效以索引版本为主，文档与知识库变更后不需要手工清理；管理端清理用于异常排查。
2. 缓存设置保存在系统设置表，Redis 不可用时精确缓存自动降级，问答与引用仍可用。
3. 深度问答开启前先确认模型可用；开启后可在用户端能力接口确认当前知识库是否可见入口。
4. 站内通知每 60 秒刷新未读数；通知失败不阻断反馈与复核提交。
5. 知识缺口扫描建议每周执行一次，扫描不会覆盖已解决或已忽略状态。
6. 文档复核建议每月查看一次到期清单，季度完成一次全量复核。
7. 企业微信登录依赖 Redis 暂存 state 与 access_token；Redis 不可用时登录返回 503，不影响账号密码登录。企业微信成员账号需与站内用户名一致，首次登录自动绑定到 `auth_identities`。

## 七、未完成与边界

1. 企业微信接口已实现但未用学校真实凭证联调，需提供企业 ID、应用 ID、应用密钥与可信回调地址后完成授权、回调与账号映射验收。
2. 语义缓存已实现并默认关闭，尚未用真实高并发语料评估误命中率，阈值需要在真实数据上校准。
3. 真实 300 至 500 条黄金集与正式基线仍未提供，现有评估使用样例测试集。
4. GPU 精排与容量压测未执行，当前性能数据来自本地问答抽样。
5. 备份恢复演练与多设备真机验收未执行；移动端 PWA 已具备离线缓存，仍需在 iOS、Android 与企业微信内嵌浏览器验证安装与离线行为。
6. 部门管理已提供独立页面，后端校验上级部门存在且不形成循环；部门删除仍采用停用，避免影响历史知识库与反馈归属。

## 八、移动端与治理补充

阶段三主体交付后补充以下能力：

1. 语义缓存：问题向量在同一知识库、策略、权限指纹与索引版本内比对，默认阈值 0.85，可在 0.75 到 1.0 调整，每个范围保留最近 50 条向量；命中后仍复核权限、文档版本与生效日期。
2. 部门管理：新增管理端「部门管理」页面，支持层级、联系人、排序、启用停用；后端校验上级部门存在、不能是自身、不能形成循环，更新接口支持清空上级与联系人。
3. 移动端二维码：PC 用户端登录页展示移动端入口二维码，优先读取 `VITE_MOBILE_URL`，未配置时使用当前主机加 5176；本机地址下仍生成二维码并提示仅本机可用，手机访问需改用局域网地址或配置 `VITE_MOBILE_URL`。
4. PWA 与离线：移动端构建带 Web App Manifest、图标与 Service Worker，页面导航网络优先并回退缓存，静态资源缓存优先，业务接口不缓存；离线时移动端顶部提示，页面可浏览但问答需联网。
5. 开发与部署：Vite 开发服务监听 `0.0.0.0`，便于手机通过局域网扫码访问；生产环境需在部署域名下设置 `VITE_MOBILE_URL`。
6. 验证：后端测试 73 项通过；新增语义键隔离与余弦相似度测试；三端构建通过；移动端离线提示与二维码入口在构建产物中生效。

## 九、后续建议

1. 优先补齐真实黄金集，按部门建立 30 至 50 条测试集后再开放部门。
2. 为公开库建立独立责任人，避免公开内容长期无人复核。
3. 每周查看知识缺口与零引用率，按缺少文档、文档过期、检索问题与模型问题分类处理。
4. 在真实设备上完成 360、390、430 像素与弱网验收，再对企业微信内嵌浏览器做兼容性检查。
5. 学校提供企业微信凭证后，按 `WECOM_CORP_ID`、`WECOM_AGENT_ID`、`WECOM_SECRET`、`WECOM_REDIRECT_URI` 完成配置，验收静默授权、未绑定提示与换绑流程。
